# Viva question banks

One file per project, 30 questions each, 750 in total.

Each file follows the same four part structure:

| Section | Covers | Roughly |
|---|---|---|
| A | Kotlin and Android basics | Q1 to Q7 |
| B | Retrofit, coroutines and networking | Q8 to Q15 |
| C | That project's specific API and data quirks | Q16 to Q24 |
| D | Edge cases, design decisions and extensions | Q25 to Q30 |

Sections A and B are common ground, so a student who built any of the 25 projects
should be able to answer them. Sections C and D are written against the exact API
that project uses, including its real awkward parts: the numbered ingredient fields
in TheMealDB, the `"N/A"` strings in OMDb, the cleartext HTTP problem in Open Notify
and Hipolabs, the nested `message` field that changes type in Dog CEO.

Ask 8 to 12 questions in a typical 10 minute viva: two or three from A and B to
confirm the fundamentals, then mostly C and D, which are hard to answer without
having actually built and debugged the thing.
